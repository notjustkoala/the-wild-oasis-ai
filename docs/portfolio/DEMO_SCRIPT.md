# Five-Minute Demo Script

## 演示前检查（不计时）

- 使用专用演示环境和合成数据；不要展示 `.env`、Network authorization header、真实邮箱、Token 或供应商控制台。
- 顾客端与员工端的实际 HTTPS URL 必须已登记并通过 `npm run smoke:production`。未配置时明确说“本地演示”，不要展示占位域名。
- 准备一个可用房型、一个带合成特殊留言的订单、一个可查询日期范围和一个只读/未授权会话。只读到店查询可用固定日期 `2026-08-31`；相对日期“明天”可能正确返回空结果。
- 分别预先打开 `DEMO_ADMIN` 与 `DEMO_STAFF` 的独立浏览器 profile/tab：Briefing route 保持 admin-only，第二段只用 `DEMO_ADMIN`；第三段切到 `DEMO_STAFF` 演示 Copilot。不要为简化演示扩大生产权限。
- 打开 [AI Eval Report](AI_EVAL_REPORT.md) 和 [架构图](assets/architecture.svg) 作为网络异常备援。

## 0:00–0:30 — 问题与边界

话术：这是一个双端 AI 住宿平台。顾客用自然语言找房和问政策，员工处理风险与经营问题；模型只负责理解和编排，库存、价格、权限与写入由工具、RLS 和人工审批控制。

展示：双端首页或架构图，指明 Guest、Staff、BFF、Supabase 和模型边界。

## 0:30–1:45 — 1. 顾客：复杂需求到预订预填

建议输入（使用演示日期按库存调整）：

> 2027-01-10 到 2027-01-13，2 位客人，总预算 1200 美元，希望安静。请推荐最多三间小屋并说明理由。

操作与讲解：

1. 发送需求，指出流式状态和被调用的库存/政策工具。
2. 展示推荐卡的日期、人数、价格与约束说明；强调价格不是模型心算。
3. 点击 **Adopt plan**，展示预订表单已预填但尚未创建订单。
4. 不点击最终提交，说明受信 server action 会重新加载价格、容量和重叠区间。

切换条件：超过 20 秒仍无可讲结果时，立即用 Guest fixture success 截图说明 UI，再进入下一段；不要在台上无限等待。

## 1:45–2:45 — 2. 员工：特殊留言到风险 Briefing

账号：切到专用 `DEMO_ADMIN`。Briefing 的服务端鉴权只接受
`app_metadata.role=admin`；`DEMO_STAFF` 不能用于这一段。

操作与讲解：

1. 打开预置的合成订单，先指向原始特殊留言仍然可见。
2. 触发或读取 Risk Briefing，展示 severity、tags、actions、confidence 与 stale/cache 状态。
3. 标记一个标签为部分正确并给出不含个人信息的纠正。
4. 说明生成失败不会禁用入住、退房或普通订单操作。

隐私点：模型只收到规则脱敏后的留言；无法安全脱敏时失败关闭，订单 ID、客人记录与完整数据库行不会进入模型输入。

## 2:45–4:10 — 3. Copilot：经营问题到人工审批

账号：切到 `DEMO_STAFF`，展示 staff 角色可以使用 Copilot，但这不授予
admin-only Briefing 权限。

建议只读问题：

> 对比这个月的入住相关订单和收入，并列出需要关注的订单。

操作与讲解：

1. 展示 KPI、图表、订单卡、tool timeline 和 source IDs。
2. 说明 dashboard 指标口径：日期字段、取消订单和 `totalPrice`/`extrasPrice` 不重复相加。
3. 对事先确认可写的演示订单发明确写请求，例如 `为订单 518 起草内部备注：演示：入住前人工确认准备情况。`。核对原备注与替换内容，员工点击 **Submit for approval**。
4. 切换到另一位 `DEMO_ADMIN`，从 **Approvals** 查看该申请。拒绝需填写原因；批准需核对完整替换内容并明确确认。员工不能自批，未提交草稿不在管理员待办中。
5. 员工从 **Request** 查看结果和历史，并在订单详情核对 Internal note；说明批准仅替换 `internalNote`，保留普通字段，原备注已变化时申请冲突而不写入。演示前保存原备注，结束后按 [完整审批验收指南](../APPROVAL_WORKFLOW_ACCEPTANCE.md) 恢复。

没有可写的专用演示订单时只展示草稿与既有历史，不提交或批准未知订单。详细拒绝、撤回、重复请求和冲突验收使用 [P1–P11](../APPROVAL_WORKFLOW_ACCEPTANCE.md)，不要求五分钟内跑完。

## 4:10–4:40 — 失败场景：越权被拒绝

使用未登录/非员工会话调用员工 AI 路径，展示受控 denied UI 或保存的 fixture denied 截图。解释实际 HTTP 证据覆盖未登录 401、跨源 403、无效 body 400、伪造反馈 403；fixture 截图只证明 UI，不冒充真实鉴权请求。

随后打开 [AI Eval Report](AI_EVAL_REPORT.md) 的证据分层表，展示 trace 只保留白名单 metadata，且 trace UUID 本身不能伪造反馈。

## 4:40–5:00 — 结果与诚实限制

话术：离线 69 条固定用例验证工具契约；旧 Gemini 首批为 8/10，两个失败后来分别补验通过，该批 P95 20.264 秒不能用作当前百炼指标。当前三个生成工作流为 qwen3.7-plus，政策向量为 text-embedding-v4/768；当前模型评测与费用口径见 [AI Eval Report](AI_EVAL_REPORT.md)。双端已上线，员工提交和管理员审核闭环已人工验收。
