# 内部备注审批完整流程

## 目标与权限

把 Operations Copilot 的备注草稿接入管理员审批中心。AI仅起草；员工提交自己的申请，管理员审核所有已提交申请，批准后事务内写入订单内部备注。范围保持内部备注，不自动执行退款、取消或修改订单核心字段。

| 操作 | 员工 | 管理员 |
|---|---|---|
| 创建、核对、提交自己的草稿 | 是 | 是 |
| 撤回自己的草稿或待审批申请 | 是 | 是 |
| 查看自己的申请、结果、审核原因、历史 | 是 | 是 |
| 查看全体待办和审批历史 | 否 | 是 |
| 批准、拒绝已提交申请 | 否 | 是 |

后端验证会话和受信 app_metadata.role；数据库再次验证身份和归属。侧栏隐藏不代替接口或数据库权限。列表只包含订单编号、房型、日期、备注及相关员工显示名，不返回客人联系方式或完整 Auth 数据。

## 状态与操作

- AI起草 → `draft`：仅保存在申请中，不写订单。员工核对原文后“提交审批”，或取消草稿。
- 提交 → `pending`：进入管理员待办；员工可撤回未决申请，管理员可批准或拒绝。
- 批准 → `executed`：原子记录审核人/时间、批准和执行审计，更新 `internalNote`；界面必须收到执行确认才显示成功。
- 拒绝 → `rejected`：要求原因，保留审核人/时间和审计，不改订单。
- 撤回 → `cancelled`：保留申请历史和撤回审计，不改订单。
- 原备注已变化 → `conflict`：原申请失效，不覆盖订单，明确提示重新起草申请。

既有已执行/拒绝记录保持原状；历史 pending 申请保留待审批性质。新的提交/审核/撤回都加行锁与幂等校验。审核时显示现有备注与拟写入备注，明确写入将替换原备注；用创建时的原备注快照检查并发变化。

## 页面与通知

- 管理员侧栏新增“Approvals”，待办数量定时更新；审批中心有待审批、历史筛选、订单链接、申请原文、现有备注、发起人、审核信息和事件历史。
- 员工侧栏新增“My requests”，可恢复跨刷新申请，查看草稿/待办/结果，提交或撤回自己的未决申请。
- 员工结果未读提醒持久化；查看并确认后清除。采用页面内轮询，不接邮件、Slack 或其他外部消息服务。
- Copilot卡片变为提交/撤回入口，不允许员工在卡片自行批准；可跳转申请页面，待审批状态自动刷新。
- 订单详情新增内部备注展示；决策后刷新相关订单与审批查询。
- 页面支持加载、空态、失败重试、分页、窄屏、审核中防重复操作、会话失效提示。

## 实现与验证顺序

1. 追加版本化数据库 migration：字段/状态、RLS、受控创建/提交/撤回/审核/列表/未读确认函数；不改历史 migration。
2. BFF新增列表和申请操作，管理员审核接口拒绝普通员工；全部接口验证来源、输入和会话，决策记录仅取数据库草稿。
3. Staff新页面、导航/保护路由、卡片与内部备注展示；不修改顾客生成、反馈或模型配置。
4. 离线测试覆盖越权、归属、幂等、拒绝原因、备注冲突、页面状态和持久恢复；数据库 rollback-only 场景检验真实RLS和状态变更。
5. 部署兼容的BFF/数据库/Staff，验证原生产域名和临时合成身份全链路。真实用户申请不代审批；生产验证订单写入仅在事务回滚内，或单独合成订单并完整清理。
6. 更新共享进度并交付管理员/员工快速人工验收步骤。真实运行证据放 ignored output，公开计划不含个人信息、凭据或运行ID。

## 快速人工验收

逐项操作、提问原文、状态对照、冲突保护和结束恢复见[完整人工验收清单](./APPROVAL_WORKFLOW_ACCEPTANCE.md)。

1. 员工登录：侧栏应有“My requests”，无管理员“Approvals”；直接访问`/approvals`显示无权限。
2. 在Copilot输入“为预订 518 起草内部备注：请在入住前人工确认准备情况。”：得到未提交草稿卡，先核对文字；没有员工自行批准按钮。
3. 点“Submit for approval”：状态为待管理员审核。刷新“My requests”仍能找到申请；此时订单原备注不变。
4. 管理员用另一个浏览器或无痕窗口登录：侧栏“Approvals”显示待办，打开申请查看原备注、拟写入备注和历史；核对后勾选确认并批准。
5. 订单详情显示新内部备注；员工“My requests”显示已批准保存、审核信息及未读提醒，点“Mark as read”后刷新不再提醒。
6. 再提交新草稿：管理员填写原因拒绝；员工能查看原因，订单备注保持不变。
7. 员工再提交一条并撤回：管理员刷新待办不再包含它，历史显示已撤回；原订单备注保持不变。
8. 关闭面板/刷新后通过“My requests”恢复草稿及待审批申请；重复点击提交或批准不应产生重复执行。跨员工查看与直接调用批准接口均须被拒绝。

这些动作会真实修改演示订单的内部备注；不要在真实业务订单上使用测试文字。付款、日期、房型、人数和订单状态不受这条审批流修改。
