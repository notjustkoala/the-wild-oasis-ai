## 任务 1: 分层测试与固定 Eval（F05-02/03）

**文件**:
- 创建/修改: 网站 `tests/ai/fixtures/`、`tests/ai/evals/`、脚本及 `package.json`。

**实现**:
- 至少 50 条、不超过 100 条 JSONL，具有稳定 id、surface、input、场景、expectedTools/forbiddenTools/hardConstraints/expectedCitationIds 中适用的字段。
- 覆盖信息缺失、约束冲突、无结果、注入、越权、审批拒绝、工具错误、取消、多轮修改。执行真实生产函数和 Agent 的 Mock 测试，不能根据预期直接伪造成功输出。
- 统一报告保存 JSON/Markdown，区分离线契约、合成检索与真实模型；指标分母仅含适用样本，报告跳过/失败/执行错误。失败或数据格式错误必须非零退出。
- 复用原工具/授权/审批和 Agent 测试；增加 runner 本身的错误与指标边界测试。

**验证**:
- 运行: `npm run eval:ai`、相关 Vitest。
- 检查: 默认不联网；故意不满足约束的结果会失败；重复执行语义结果一致；硬约束不是只检查字段存在。

## 任务 2: 观测、反馈与隐私（F05-04）

**文件**:
- 创建/修改: 网站 `app/_ai/observability/`、反馈路由、迁移、SQL 测试、三个生成入口、两端 UI。

**实现**:
- 使用 `vercel:ai-sdk` 技能核对 callbacks；使用 `supabase:supabase` 技能创建和验证迁移。
- 元数据白名单、traceId、duration、真实首文本 TTFT、usage、版本、工具状态；成功/失败/超时/取消/拒绝/限流区分；只完成一次，写入有界且失败不影响业务。
- 保存受控评分和 traceId 的关联；签名凭证验证、防伪造/过期/跨 run、严格 body 大小限制；员工 CORS 可读取追踪 header。
- UI 能看到可用于排错的请求编号，提交反馈有成功/失败状态。管理员可通过受保护查询或报告命令按 traceId 查询元数据。
- SQL 验证匿名/普通/员工/管理员读写矩阵、客户端不能伪造 run、反馈关联/唯一性、service role 写入、回滚清理。

**验证**:
- 运行: 观测/反馈/SQL 权限测试、typecheck。
- 检查: 对包含 PII 的输入/输出/异常，仅持久化白名单；存储超时/异常不破坏原结果。

## 任务 3: 安全和降级（F05-05）

**文件**:
- 创建/修改: 持久限流模块与 service-only RPC、现有路由和安全测试。

**实现**:
- 已验证员工身份摘要或匿名共享桶作为 key；可信代理必须显式配置才能使用平台 IP，任意伪造请求头不能绕过限流。
- 并发消费原子化，429 带 Retry-After；限流存储不可用时返回友好 AI 错误，普通业务不受影响。
- 继续使用工具层权限/审批门禁，不能因为观测使用 service role 放宽经营工具权限。
- 验证模型不可用、超时、取消、工具失败、审批拒绝、401/403、不支持输入等路径的状态与 traceId。

**验证**:
- 运行: 安全单元/集成测试及 SQL 并发边界测试。
- 检查: 越权与未审批写入成功次数为 0；失败绝不能被计为成功。

## 任务 4: E2E、指标和收尾（F05-06/07）

**文件**:
- 创建/修改: 浏览器配置、两端 E2E、显式 live 配置、报告脚本、README、进度文档。

**实现**:
- 使用 Playwright 技能验证双端关键 UI/网络流程，明确标注 Mock HTTP 边界；普通筛选/预订/后台原功能在 AI 故障下可继续。
- 显式运行 10 个固定场景并生成成功率、P50/P95、Token/成本、工具错误与反馈报告。每条保存模式、版本和可追踪 ID；不混用模拟延迟和真实模型延迟。
- live 使用合成输入、原模型和开发数据库，严格区分真实生产函数验证和浏览器 E2E；失败经过保留。
- 补充部署前 migration、配置、清理和诊断说明；运行两端 check，再按技能顺序审查。

**验证**:
- 运行: 两端 `npm run check`、网站 `npm run eval:ai`、两端 `npm run test:e2e` 及安全 E2E。
- 检查: 新依赖固定版本及 lockfile；全量验证无新回归，报告不夸大证据。
